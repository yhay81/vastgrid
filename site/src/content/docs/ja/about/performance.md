以下の数値はすべて Apple M2 Pro で計測しました。表ごとに、いつ、何で計測したか、どうすればもう一度計測できるかを書いています。時間はマシンによって変わりますが、React のコミットの回数は変わりません。

## ブラウザーでのグリッド

ベンチマーク（`examples/bench`）は、メモリエンジンがページか Web Worker の中で持つ 100 万行・8 列（整数、文字列、浮動小数点数、日付、真偽値）の表にグリッドをマウントし、エンドツーエンドのテストが Chromium 156 と Playwright（ヘッドレス、60 Hz）で計測します。2026-10-24 に Node.js 24 と React 19.3.1 で計測し、範囲は最後の 4 回のものです。比較のために vastgrid 0.1 も載せています。

| 計測 | vastgrid 0.1 | 0.2（エンジンはページ） | 0.2（エンジンは Worker） |
| --- | ---: | ---: | ---: |
| マウントから最初の行が画面に出るまで | 46–65 ms | 43–49 ms | 36–49 ms |
| 矢印キー 1 回の React のコミット | 1 | 1 | 1 |
| キーを押してから次のフレームまで（p95） | 13.8–14.1 ms | 13.4–14.1 ms | 13.5–13.9 ms |
| 100 フレームのスクロール中の React のコミット | 0 | 0 | 0 |
| スクロール中のフレームの間隔（p95） | 16.7–16.8 ms | 16.7–16.8 ms | 16.7–16.8 ms |
| 浮動小数点数の列で並べ替え、結果が画面に出るまで | 494–516 ms | 85–98 ms | 112–113 ms |
| その間のページの最も長いタスク | 490–512 ms | 81–93 ms | なし |
| ページの JavaScript のヒープ | 190 MB | 202 MB | 10 MB |

グリッドは 60 Hz でフレームを落とさずにスクロールし、キー 1 回で React を 1 回コミットします。並べ替えは vastgrid 0.1 の 5〜6 倍速く、エンジンを Worker に置けば、100 万行を並べ替える間もページは止まらず、表を何も持ちません。

## 予算

次のどれかを超えるとエンドツーエンドのテストが失敗するので、どのリリースでも守られています。

| 計測 | 予算 |
| --- | --- |
| 矢印キー 1 回の React のコミット | 1 回以下 |
| 100 フレームのスクロール中の React のコミット | 0 回 |
| スクロール中のフレームの間隔（p95） | 25 ms 未満 |
| キーを押してから次のフレームまで（p95） | 25 ms 未満 |
| マウントから最初の行が画面に出るまで（メモリ上の 100 万行） | 300 ms 未満 |
| メモリ上の表と `DataGrid` でページが最初に読むもの（圧縮後、gzip） | 200 KB 未満 |

2026-10-27 には、ページが最初に読むのは gzip で 100.9 KB、全部で 133.2 KB でした。列とセルのメニュー、ツールバーのメニュー、検索のバー、詳細パネルは、最初に開いたときに読みます。`npm run build` の後の `npm run size` で計測します。

## DuckDB のエンジン

2026-10-27 に、Node.js 24.22.1、DuckDB の Node.js API 2.0.0-r.1、DuckDB のスレッド 8、メモリの上限 2 GB で計測しました。数値はどれも 3 回の中央値です。要求はどれも、エンジンのメッセージを通して 8 列すべての 256 行を読みます。Arrow への変換と読み取りを含み、HTTP と描画は含みません。並べ替えは `price DESC`、絞り込みは `city = 'Tokyo'` です。深い位置の読み取りは、完成したビューの 25%・50%・75%・99% の位置と末尾での 5 回の読み取りです。

| ファイルとプラン | 最初の行 | 深い位置の読み取り（p50 / 最大） |
| --- | ---: | ---: |
| Parquet・1 億行（1.38 GB）の並べ替え | 953 ms | 700 / 931 ms |
| Parquet・1 億行の絞り込み | 192 ms | 21 / 23 ms |
| CSV・1,000 万行（735 MB）の並べ替え | 55 ms | 4.0 / 4.5 ms |
| CSV・1,000 万行の絞り込み | 124 ms | 3.0 / 3.2 ms |

- 100 万行以上の並べ替えの最初の行は、top-N の問い合わせで、完成したビューと同じ順番で取り出し、残りはその間に作ります。完成までにかかる時間は、Parquet でさらに 3.0 秒、CSV で 0.9 秒です。
- 1 億行のビューは、並べ替えた複製を作る 2,000 万行を超えるので、行の順番だけを持ちます。そのため深い位置の読み取りは、ファイルのあちこちから行を集めます。CSV のビューは並べ替えた複製で、数ミリ秒で読めます。
- 計測の全体で、プロセスのメモリは最大 2.74 GB、セッションのフォルダーは最大 0.84 GB でした。

Apple シリコンのノートパソコンで、2 つのセルの保存は 20 万行の CSV で約 60 ms、200 万行で 0.3 秒です。100 万行・4 列の並べ替えたビューの書き出しは、CSV で 0.3 秒、Parquet で 0.1 秒、JSON で 0.2 秒、Excel のブックで 2.2 秒です。

方法、このバージョンより前の数値、もう一度計測するコマンドは [`views-benchmark.md`](https://github.com/yhay81/vastgrid/blob/main/docs/views-benchmark.md) にあります。

## メモリエンジン

2026-10-27 に Node.js 24.22.1 で計測しました。要求はどれもエンジンのメッセージを通し、ファイルはページが `File` で渡すように渡しています。Worker、ページ、描画は含みません。1 回の計測で、単位はミリ秒、`maxBytes` は既定の 1 GiB です。

| 要求 | 100 万行の CSV（69 MB） | 100 万行の Parquet（13 MB） | 1,000 万行の CSV（701 MB） | 1,000 万行の Parquet（132 MB） |
| --- | ---: | ---: | ---: | ---: |
| 開く | 1,059 | 26 | 10,499 | 38 |
| 最初の 256 行 | 9.3 | 201 | 6.8 | 206 |
| 浮動小数点数で並べ替え | 91 | 1,078 | 881 | 8,723 |
| 文字列で並べ替え | 483 | 247 | 5,040 | 2,880 |
| 絞り込んでからタイムスタンプで並べ替え | 189 | 100 | 2,470 | 1,813 |
| 3 つの集計でグループ化 | 411 | 322 | 4,974 | 3,523 |
| すべての行を CSV で書き出し | 1,450 | 1,324 | 14,785 | 13,653 |
| セルを 1 つ書き込む | 0.5 | 0.3 | 0.4 | 0.3 |

100 万行の CSV は開いた後に約 60 MB、Parquet は列を読むまで 1 MB です。列が `maxBytes` に収まらないファイルも開け、要求は必要な列を読みます。一度に `maxBytes` より多くを必要とする要求は `load_failed` で失敗し、表は開いたままです。そのようなファイルには、ディスクにあふれさせられる DuckDB のエンジンを使ってください。

すべての要求、メモリ、限界、もう一度計測するコマンドは [`memory-engine-benchmark.md`](https://github.com/yhay81/vastgrid/blob/main/docs/memory-engine-benchmark.md) にあります。
