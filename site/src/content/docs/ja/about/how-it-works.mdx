グリッドはファイルやデータベースについて何も知りません。`DataGrid` はストアが持つものを描き、ストアはドキュメント、セッション、行のまとまりを持って、トランスポートを通してエンジンに行を求めます。どのエンジンも同じメッセージに答えるので、ページの中の行でも、Web Worker の中のファイルでも、サーバーの 1 億行のファイルでも、グリッドは同じように動きます。描く重さは、表が 100 行でも 10 億行でも変わりません。

## 描画

セルはキャンバスに描きます。メニュー、パネル、検索のバー、セルの編集欄は、その上に重ねた DOM の要素です。画面の行を表す見えない ARIA のグリッドが、スクリーンリーダーにセルを伝えます。スクロールでは React を描画せずにキャンバスだけを描きます。矢印キー 1 回では、ARIA のグリッドのアクティブなセルを動かすために React が 1 回コミットします。React がツールバー、ステータスバー、パネルを描き直すのは、表示する内容が変わったときです。

キャンバスは色と文字の設定をグリッドのルートの [CSS のカスタムプロパティ](/ja/guides/theming/)から読むので、セルもほかの部分と同じように CSS で変えられます。

## スクロール

キャンバスの上に透明のスクロール用の要素を重ねているので、ホイール、トラックパッド、スクロールバーは OS 本来の動きのままです。ブラウザーには要素の大きさの上限があるため（Chromium で約 1,677 万 px。24 px の行では 70 万行に届きません）、`ScrollAxis` がスクロールの実際の位置を仮想の位置に写します。小さな移動はそのままの量だけ動かし、大きな移動と両端は比例で写します。どの行にも、スクロールバーとキーで届きます。

## 行の読み込み

キャンバスは毎フレーム、見えている行と列をストアに伝えます。ストアは、それらの列の 256 行ずつのまとまりのうち足りないものを、画面の行と、その上下 1 画面分（少なくとも 32 行）について読みます。まとまりは 64 MiB まで持ち、それを超えると最も長く使っていないものから捨てます。まとまりは Apache Arrow で届きます。HTTP では答えにバイト列として添えられ、Web Worker からはコピーせずに移されます。エンジンは表示用に長い文字列を切ります（DuckDB のエンジンでは 2,000 文字）。コピーとセルのメニューの「値の全体を表示」では、値の全体を読みます。

行は React が見る状態には入りません。ストアのスナップショットが持つのは、ドキュメント、セッション、表とビューについてエンジンが答えたことです。キャンバスは行をキャッシュから直接読み、コンポーネントは `useGridRows` で読みます。

## ビューとコマンド

ドキュメントのプラン（計算列、条件、グループ、並べ替え）がビューで、プランの正規形のハッシュで区別します。プランが変わると、ストアは前のビューを画面に残したまま新しいビューを読み、新しい行の表示と、同じレコードへの選択範囲の移動を一度に行います。並べ替えで空の行がちらつくことはありません。

変更はすべてコマンド（`sort.set`、`filter.column`、`edit.set`、`select` など）で、`vastgrid-spec` の `applyCommand` が、ドキュメントとセッションに純粋な関数として適用します。グリッドのメニューとキー、自作のボタン、VS Code の拡張機能、AI のエージェントが同じコマンドを送るので、どれも同じ動きになります。プラン、コマンド、メッセージは[仕様](https://github.com/yhay81/vastgrid/blob/main/docs/v2-spec.md)が定め、適合性のテストの一式で、エンジンが同じ答えを返すことを確かめています。

## メモリエンジン

`vastgrid-js` は表を型付きの列として持ちます。テキストのファイルは、`maxBytes`（既定は 1 GiB）に収まれば、開くときに少しずつ読んで列にします。収まらなければ索引だけを作り、行はまとまりごとにファイルから読みます。Parquet のファイルは、ディスク上でも HTTP の範囲指定で読む URL でも、開くときはフッターだけを読み、行はそれを持つ行グループから読みます。並べ替え、絞り込み、グループ化は必要な列を丸ごと読み、場所が足りなくなると最も長く使っていない列から忘れます。並べ替えでは、列の値の順位を一度だけ求め、その順位で並べ替えます。Web Worker に置けば、Worker が並べ替える間もページは描き続け、表を何も持ちません。

## DuckDB のエンジン

- **開く。** 区切りのテキスト、JSON Lines、Excel のシートは、セッションのデータベースの中で DuckDB の表になります。ファイルを読み込む間は、最初の 1,000 行をプレビューから返します。Parquet はファイルのまま読み、読み込みはありません。DuckDB が読めない文字コード（Shift_JIS・EUC-JP）は先に変換します。
- **ビュー。** 並べ替えと絞り込みはビューを作ります。2,000 万行までの表では並べ替えた複製を作るので、行のまとまりを数ミリ秒で取り出せます。それより大きな表では行の順番だけを作るので、時間も一時領域もわずかで済みます。100 万行以上の並べ替えでは、まず先頭の 1,000 行を top-N の問い合わせで、完成したビューと同じ順番で取り出して表示し、残りをその間に作ります。作ったビューは 8 つまで残して使い回します。
- **隔離。** DuckDB が読めるのは、許可したフォルダーの中の、実際の場所にあるファイルだけで、その後は外部へのアクセスを止めます。SQL はすべて `vastgrid-sql` が組み立てたもので、値は必ずパラメーターで渡します。
- **保存。** 書き込んだセルはセッションのデータベースにあります。CSV と TSV のファイルに保存するときは、編集していないバイトをすべてそのまま残してセルを書き込みます。読んだ後にディスク上でファイルが変わっていれば、保存しません。

[既存のビューアーとグリッドの調査](https://github.com/yhay81/vastgrid/blob/main/docs/research.ja.md)と[作り直しの判断](https://github.com/yhay81/vastgrid/blob/main/docs/rebuild-decision.ja.md)に、これらを選んだ理由があります。
