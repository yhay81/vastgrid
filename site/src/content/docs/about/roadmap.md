---
title: Roadmap
description: What is planned for vastgrid.
---

Cell editing and byte-preserving CSV write-back are implemented in v1. The unreleased v2 rebuild is tracked in [#33](https://github.com/yhay81/vastgrid/issues/33).

v2 rejects out-of-range typed values and malformed Unicode instead of silently changing them in Arrow conversion. Float32 text input is rounded before writing, and numeric overflow is rejected. The [v2 specification](https://github.com/yhay81/vastgrid/blob/main/docs/v2-spec.md#22-values-in-json) defines these rules.

v2's DuckDB engine writes cells of files, kept apart from the file, with conflict checks and undo, and saves them into CSV and TSV files with the bytes that were not edited kept as they are; the grid saves with ⌘S or Ctrl+S. Files that change on disk are read again, and unsaved edits are kept until you discard them ([#37](https://github.com/yhay81/vastgrid/issues/37)). Views and whole tables are exported as CSV, TSV, Parquet, JSON and Excel on the server ([#38](https://github.com/yhay81/vastgrid/issues/38)). Formulas in v1's language compile to plan expressions, v1's saved formulas migrate, and the toolbar's Formulas menu adds, changes, renames and removes derived columns ([#39](https://github.com/yhay81/vastgrid/issues/39)). The standard panels and menus are under way ([#42](https://github.com/yhay81/vastgrid/issues/42)): each column has a menu that sorts by it, filters it by a list of its values with their counts or by a condition, shows its statistics, sets its total in a totals row, groups by it, and fits, freezes and hides it; the toolbar's Group menu chooses the keys, measures and pivot columns, the Conditions menu combines conditions across columns with AND and OR, and the Columns menu shows, hides and moves columns. Each column's Format… sets its label, alignment, wrapping, number or date format and conditional colors. Rows can be checked, and a detail panel shows every column of the active row. Column groups, links and buttons in cells, custom drawing and filling are in, and [v2-from-v1.md](https://github.com/yhay81/vastgrid/blob/main/docs/v2-from-v1.md) maps v1's features to v2. Find (⌘F), the cell menu and moving columns by dragging their headers are in too. Menus and panels load when they first open, and CI keeps what a page loads first under 100 KB with gzip. Messages are checked to their limits all through, plans and values included, and errors stay within them whatever a request holds ([#46](https://github.com/yhay81/vastgrid/issues/46)). An MCP App ([#40](https://github.com/yhay81/vastgrid/issues/40)) opens files of any size in a grid inside the chat, where the agent and the person work on the same state with the same commands ([mcp-app.md](https://github.com/yhay81/vastgrid/blob/main/docs/mcp-app.md)). In VS Code ([#41](https://github.com/yhay81/vastgrid/issues/41)), files of any size open in a grid as an editor, read by DuckDB in the extension, and CSV and TSV files are edited and saved with VS Code's Save, Save As and Revert ([vscode.md](https://github.com/yhay81/vastgrid/blob/main/docs/vscode.md)). The JavaScript engine computes derived columns, conditions and the search with every function of the specification, and passes every case of the conformance corpus that uses them. Next in it ([#43](https://github.com/yhay81/vastgrid/issues/43)): groups and pivots, typed columns, and files in the browser.

Ideas and use cases are welcome in [the issues](https://github.com/yhay81/vastgrid/issues). Open one
before a larger pull request, as [CONTRIBUTING.md](https://github.com/yhay81/vastgrid/blob/main/CONTRIBUTING.md)
describes.
